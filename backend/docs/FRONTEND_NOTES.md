# 앱·운영자 웹 전달 사항

서버 틀을 만들며 확인한, 앱(Kotlin)과 운영자 웹이 맞춰야 할 내용입니다. 기준은 API 명세서 3.9.0입니다.

## 서버와 통신할 때

로그인이 필요한 API에서 `401`이 오면 `code`를 먼저 봅니다. `UNAUTHORIZED`(토큰 만료)면 `POST /api/auth/refresh`로 재발급한 뒤 다시 요청하고, `TOKEN_REVOKED`(탈퇴·비밀번호 변경으로 무효)면 재발급하지 말고 저장된 토큰을 지운 뒤 로그인 화면으로 보냅니다. `409 UNPAID_DEBT_EXISTS`는 어느 API에서든 올 수 있으니 공통 처리로 미수금 화면(충전·납부)으로 이동합니다.

본문이 없는 성공 응답은 `204`이므로 Retrofit에서 `suspend fun xxx(): Response<Unit>`으로 선언합니다. 일시는 요청·응답 모두 `2026-10-16T23:30:00+09:00` 형식이어야 하며, 오프셋이 없거나 `Z`면 서버가 `400 INVALID_DATETIME_FORMAT`을 돌려줍니다. 모든 enum에는 `UNKNOWN` 항목을 두어, 서버가 새 코드값을 추가해도 앱이 죽지 않게 합니다.

운영자 웹의 이미지(캡처본·영수증)는 토큰이 필요해서 `<img src>`로는 열리지 않습니다. `fetch(url, {headers: {Authorization}})` → `blob()` → `URL.createObjectURL()`로 표시합니다. 실시간은 STOMP `/ws`에 `Authorization: Bearer` 헤더로 연결하고 `/topic/pots/{potId}`를 구독합니다. `POT_UPDATED`를 받으면 방 상세를 다시 조회하고, `CHAT_MESSAGE`는 payload를 바로 화면에 붙입니다. 채팅 전송은 STOMP가 아니라 `POST /api/pots/{potId}/messages`입니다.

## Figma 플로우차트에서 명세와 다른 곳

방장 미도착 시스템 순서도에 "동승자가 '방 폭파' 클릭"이 남아 있는데, 방 폭파 API는 삭제되었고 스케줄러가 자동 해산합니다(UI 흐름도는 이미 맞음). 도착 확인 UI의 반경은 100m가 아니라 50m입니다. 충전 흐름의 "외부 PG 또는 더미 결제"는 캡스톤 범위 밖이며, 앱의 더미 충전은 `DUMMY_CHARGE_NOT_ALLOWED`로 막히고 시연 충전은 운영자 잔액 조정만 씁니다. 미수금 납부 UI의 "즉시 납부(카드, 계좌)"·"계좌 입금"은 명세상 '지갑 잔액에서 납부' 또는 '충전·조정 시 자동 납부'입니다.

방 수정 순서도의 "출발 시간/인원 수정"은 틀렸고, 수정 가능한 것은 제목과 오픈채팅 링크뿐입니다. 방 생성 시간 판단은 15분 기준 화살표 라벨이 뒤바뀌어 있고, 24시간 초과(`DEPARTURE_TIME_TOO_FAR`) 분기가 빠져 있습니다. 회원가입 기본 정보에 이메일·비밀번호와 필수 출금 계좌 등록이 빠져 있고, 탈퇴 화면에는 잔액 소멸 동의 체크가 필요합니다. 평가 UI의 사유 입력은 "(필수X)"가 아니라 평균 3점 미만이면 필수(`BAD_REASON_REQUIRED`)입니다. 신고 심사 UI는 "승인→반려 완료", "반려→승인 및 제재" 화살표 라벨이 서로 바뀌어 있습니다.
